## Архитектура (ключевое)

- `src/domain/types.ts` — `EquipmentModel`, `TechCardRow`, `FailureRecord`,
  `ReferenceData`, `Characteristic`, `ActionItem`, `ClassifierDef`. Каждое
  значение имеет `source` (`classifier` | `manual` | `ai` | `document` |
  `web` | `analog`) + `lockedByExpert` (замок).
- `src/domain/normalize.ts` — правила нормализации кода модели п.8.3 ТЗ.
  **30 из 30 примеров проходят, правила трогать без причины не надо.**
- `src/domain/ai.ts` — интерфейс `AiProvider` + `noopAiProvider`.
- `src/domain/openai.ts` — реальная реализация поверх OpenAI. Кэш в
  `localStorage` по fingerprint входа. Счётчик через события
  `nsi:ai-usage`. Ключ — `nsi_openai_api_key` (хранится только в
  браузере пользователя, на наш сервер не уходит).
- `src/parsers/*.ts` — автоопределение типа xlsx по заголовкам.
  Порядок детекции в `autoImport.ts`: hierarchy → classifier →
  classification → actions → reference → characteristics → unknown.
  **Правила порядка важны**, reference должен стоять ДО characteristics.
- `src/store.ts` — zustand стор со всеми действиями. `applyClassification`
  и `classifyByClassifier` **не перезаписывают** модели, у которых класс
  уже определён прямой привязкой или вручную — это чинило баг «0%».
- `src/components/ModelCard.tsx` — карточка модели с 9 вкладками.
  Все внутренние компоненты `*Tab` объявлены inline внутри `ModelCard`,
  чтобы замыкать `cls`, `sub`, `update`, `classifier`. Не разбивать на
  внешние файлы без причины — это ломает доступ.
- `src/components/App.tsx` — шапка, счётчик качества, кнопка ИИ.
- `src/components/Toolbar.tsx` — 5 кнопок + «Классифицировать ИИ».

## Что сделано (этапы 1–9)

**1–3.** Иерархия, нормализация, классификатор (три пути: файл с
привязками, эвристика с ключевыми словами, ИИ). Классификатор умеет
принимать файлы без keywords и не молчит — показывает, чего не хватает.

**4–5.** Документы модели: загрузка локального файла (PDF/DOCX/TXT) или
ссылки, распознавание через pdf.js + mammoth, сохраняем только
`parsedText` (сам файл не грузим). Характеристики: приоритетные сверху
со ★, источник в колонке, замок, извлечение из документа.

**6.** Импорт характеристик по файлу «Результирующий» (30/29 моделей,
199 полей). Аналоги: сравнительная таблица по приоритетным
характеристикам, подсветка совпадений.

**7.** Техкарты (единое окно, таблица: Компонент · Операция ·
ВВ · Профессия · Разряд · Норм-ч · ТМЦ · Тип ТМЦ · Ед. · Кол-во).
Надёжность: импорт истории отказов, MTBF/MTTR/λ, фоллбек «по аналогам».
Четыре справочника (ВВ, операции, специальности, ед.) грузятся одной
кнопкой «Загрузить», автодополнение в техкартах идёт из них.

**8.** ИИ (OpenAI gpt-4o-mini): три кнопки по карточке («Спросить ИИ»,
«Извлечь через ИИ», «Предложить через ИИ») + модалка настроек с полем
ключа, счётчиком расхода и очисткой кэша. В шапке — кнопка «ИИ · $N».

**9.** Спецификации (BOM + APL), график ППР на модель, оценка качества
в шапке («Полнота хар-к N% · Проверено X/Y»), кнопка
«Классифицировать ИИ» (пакет).

## Баги и важные правки

- «классификатор 0%» — был, потому что `classifyByClassifier`
  перезаписывал confidence=0 поверх прямой привязки. Починено: не
  трогаем модели с `source='classifier'` или `'manual'`. Процент
  скрыт в UI, когда `confidence >= 1` или source = manual/unresolved.
- ВВ ист и инт не затирают друг друга; `applyActions` дописывает с
  сохранением source.
- Excel-даты в истории отказов: поддержка Excel serial (25569…80000),
  dd.mm.yyyy, dd/mm/yyyy, ISO, Date.parse.
- `инструмент` НЕ попадает в BOM/APL — по явному требованию заказчика в
  созвоне 00:46:35 (несмотря на формальный текст ТЗ п.6.6.4).
